## Why (owner, 21 Oct)

Mr Akbar wants to see, for the website channel, the TOTAL GROSS enquiries,
what is happening with each one, the ACTUAL (valid) enquiries and the
CONVERSIONS. Today the website enquiries live only in the dashboard
(Marketing > Growth > Website, e.g. `?tab=marketing&gtab=growth&gchan=website
&from=2026-10-01&to=2026-10-21`), while the team's follow-up and conversion
work lives in the Inhouse Lead Tracker Google Sheet
(`config/sheet-mapping.ts` key `leadTracker`). They never meet.

## The pattern to reuse

`lib/sync/leadMirror.ts` already does this for the Araby workbook: it appends
widget leads into a tab in the team's own format, writes only its own
columns, never touches the team's columns, dedupes by phone + minute,
continues Lead IDs, and keeps a formula-driven summary tab. Reuse its
helpers and conventions (`getSheetsWriteClient`, dedupe, ID continuation,
summary-tab creation) rather than writing a second implementation.

## Part A — Mirror tab `Website Enquiries (auto)` in the Inhouse Lead Tracker

1. Population = EXACTLY the enquiries the dashboard counts in the Growth
   `website` channel for a date range (`lib/growth/channelPerformance.ts`,
   the `countEnquiry(..., 'website', ...)` path and the website attribution
   rules in `lib/growth/attribution.ts`). Factor out one shared selector so
   the sheet and the dashboard cannot disagree; do not re-derive the rule.
   Backfill from 1 Oct 2026, then append new ones on each sync run.
2. Machine-owned columns (written by the sync, refreshed each run):
   `Lead ID` (WEB-0001 upward, continuing the tab's own max), `Date`,
   `Time`, `Patient Name`, `Contact Number`, `Clinic / Branch` (display name
   from DN-018's canonical branch), `Service / Lane requested`,
   `Source detail` (booking widget / offer form / incomplete booking, from
   the existing source fields), `Dashboard status` (booked / attended /
   billed, from the same Growth appointment and billing matches the
   dashboard already uses; blank when unknown, never guessed),
   `Billed AED (dashboard)`.
3. Team-owned columns, in the tracker's existing style, NEVER overwritten
   by the sync: `Valid enquiry?` (dropdown: Yes / Spam / Vendor or sales /
   Job applicant / Duplicate / Existing patient admin / Wrong number),
   `1st Follow-up`, `2nd Follow-up`, `3rd Follow-up`, `Assigned To`,
   `Outcome` (dropdown: Booked / Not interested / No answer / Call back /
   Price / Other), `Conversion` (dropdown: Converted / Not converted),
   `Revenue`, `Notes / Remarks`. Add data-validation dropdowns on create.
4. Idempotent: re-runs append nothing twice; a row's team columns are
   untouched even when the machine columns refresh. Dedupe by phone +
   minute, as in leadMirror.

## Part B — Formula tab `Website Summary` (created if absent)

Date-range input cells (From / To, default month to date). Formula-driven
from the mirror tab, by branch and total:
- Gross enquiries (all rows in range)
- Actual enquiries (Valid enquiry? = Yes, plus rows not yet reviewed shown
  separately as "Not yet reviewed")
- Invalid by reason (Spam, Vendor, Job, Duplicate, Existing patient admin,
  Wrong number)
- Contacted (any follow-up filled), Booked (Outcome = Booked or Dashboard
  status booked/attended), Attended (Dashboard status attended), Converted
  (Conversion = Converted or billed), Revenue (team Revenue, else Billed AED)
- Rates: actual / gross, booked / actual, converted / actual
Plain formulas only (no Apps Script), so the team can see how each number
is made.

## Part C — Read the team's verdicts back into the dashboard

On the Growth website channel, add a compact line: `Gross N · Actual N ·
Not yet reviewed N · Booked N · Converted N`, reading `Valid enquiry?`,
`Outcome` and `Conversion` back from the mirror tab via the existing sheet
sync. If the tab cannot be read, show the existing numbers and a short
"team review unavailable" note; never fail the page.

## Landmines

- The `leadTracker` sync has `discoverTabs: true`. The new tabs MUST be
  excluded from that discovery (and from every lead count), or every
  website enquiry is double-counted as a tracker lead. Add a test.
- Never write to any existing tab. Create the two new tabs only.
- The sync's service account needs EDITOR access on the Inhouse Lead
  Tracker (Viewer is enough today). Detect a permission error and report
  "needs Editor access" in the run result instead of failing other syncs;
  Claude will ask the owner to grant it.
- Run inside the existing scheduled sync (same place leadMirror runs), with
  its own result entry; no new cron.
- Counts must reconcile: for any range, sheet gross = dashboard website
  enquiries for the same range. Add a test that builds both from one
  synthetic fixture and asserts equality.
