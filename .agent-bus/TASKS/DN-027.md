## Production facts (verified by Claude read-only, 17 Oct)

`lane_e.competitor_snapshots`, domain `market:uae-dental`:

| fetched_at | keywords stored | errors | requests | cost USD |
|---|---:|---|---:|---:|
| 2026-10-14 | 0 | Expanded keyword list exceeds 10,000 terms; totals withheld | 16 | 1.44 |
| 2026-10-07 | 0 | same | 17 | 1.53 |
| 2026-10-06 | 25 | (older version, seeds only) | - | - |

So each weekly run pays for every expansion request, then
`buildMarketSnapshot` (`lib/analytics/demandMarket.ts`, line ~49) throws once
`requested.size > MARKET_BUDGET.maxKeywords` and the snapshot keeps NOTHING,
not even the seed volumes. Marketing > Demand to desk then shows no market
data, and the next week repeats it.

## Fix

1. Never throw away paid data. Replace the throw with a bounded selection:
   - Seeds (`marketKeywords(language)`) are ALWAYS kept.
   - Expansion terms are capped PER THEME (proposal: top 150 per theme per
     language), ranked by the search volume the expansion response already
     returns (`search_volume` on each item; check the fixture/response
     shape), ties by keyword text. Then a global cap (proposal: 3,000 per
     language) after seeds. Put both caps in `MARKET_BUDGET`.
   - Record a non-fatal note in `errors` like
     `en: expansion capped at 150 per theme (N terms dropped)` so the UI can
     say the totals are a capped sample. Do not call it a failure.
2. If the expansion response already carries `search_volume`, `cpc` and
   `competition_index` for a term, use those and do not request volumes
   again for it. Only seeds or terms without data go to the `volume`
   request. This should cut requests and cost. Measure it in tests
   (request count before/after on the fixture).
3. Budget guard stays: never exceed `MARKET_BUDGET.requests` or `maxUsd`;
   check the caps BEFORE making the volume requests, not after spending.
4. `parseMarketSnapshot` must accept a capped snapshot (errors present,
   seeds all present) and the Demand to desk page must render it with the
   capped note. Keep `version: 2` unless the shape must change; if it
   changes, bump to 3 and keep reading version 2.
5. Do not change the weekly TTL, location (2784), themes or seeds.

## Tests (extend `tests/demand-market.test.ts`, synthetic only)

- An expansion fixture yielding more than 10,000 terms produces a snapshot
  with all seeds plus capped expansion terms, no throw, a capped note, and
  no more than the configured caps.
- Ranking: higher-volume terms are kept over lower ones; deterministic tie
  order.
- Terms with volume data from expansion are not re-requested; request
  count and cost on the fixture are lower than before.
- Budget guard: request/USD limits still stop the run, with what was
  already fetched kept.
- `parseMarketSnapshot` accepts the capped snapshot; existing tests still
  pass, none weakened.
