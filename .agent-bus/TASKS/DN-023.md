**`value` is NOT NULL.** That makes DN-022 finding 1 worse than reported:
`storeBenchmarkObservations` sends `review_count` and `rating` in ONE upsert,
so when the rating is null (zero reviews, or any listing missing a rating)

clinic is only recorded in `failed`. So "store null to clear the rating"
cannot work against the real table. Do NOT add a migration to make `value`
nullable: other writers and readers assume a number.

## Part A — Rating: absence means unavailable (blocker)

1. Writer (`lib/analytics/benchmark-observations.ts`): always store
   `review_count` when the observation is valid. Store a `rating` row ONLY
   when the rating is a real number in range. Never send a null `value`.
   A missing rating is recorded as the absence of a same-day rating row.
2. Reader (`lib/performance/core.ts` `benchmarks()` and
   `lib/performance/reader.ts`), for the `benchmark` channel:
   - The latest observation for a profile is the latest `review_count`
     row. Its day is the observation day.
   - Show a rating only if a `rating` row exists for the SAME profile on
     that SAME day. Otherwise the rating is unavailable (null), even if an
     older rating row exists. Never show an older rating beside a newer
     count.
   - Use the GBP snapshot fallback for our Al Wasl profile only when there
     is NO stored `benchmark` `review_count` row for `dental-nation` up to
     `asOf`. Once a stored observation exists, the snapshot never fills
     either the count or the rating.
   - The 30-day delta still requires two real values exactly 30 days apart
     on the same profile. Keep the existing rule; a missing rating on
     either day means no rating delta.
   - Instagram `followers` behaviour must not change.
3. Tests (extend `tests/benchmark-observations.test.ts`, synthetic only):
   - Writer with zero reviews: one `review_count` row with value 0 and no
     rating row; the upsert payload never contains a null `value`
     (assert on the mocked payload). Same for a positive count with an
     incomplete rating.
   - A mocked db that REJECTS null `value` (like production) stores the
     count successfully for both cases.
   - Reader, DN-022's reproduction: Al Wasl stored `review_count = 0` on
     2026-10-11, no rating row, GBP snapshot with a 5.0 rating on
     2026-10-12 → reviews 0 dated 2026-10-11, rating null. The 5.0 must
     not appear.
   - Reader: competitor rating 4.8 on 2026-10-01, newer `review_count`
     on 2026-10-11 with no rating row → rating null, not 4.8.
   - Reader: no stored `benchmark` rows for `dental-nation` → snapshot
     fallback still used (existing behaviour preserved).
   - Email: the rendered benchmark section shows the unavailable rating
     the same way it already shows other unavailable values (no "0.0",
     no stars).
