# DN-003 — Adversarial rigor review of the Smile Club plan

STATUS: COMPLETE — review delivered 21 Sep (16 findings), corrections applied to the plan as rev. 3.

Mode: repo
Branch: codex/DN-003

Goal: the Smile Club growth plan is read by a CEO with E&Y + McKinsey
history. Review it the way a McKinsey engagement manager reviews a
first-year associate's deck: hunt for logical loopholes, dangling numbers,
circular reasoning, unsupported claims, inconsistent definitions and loose
connectivity between sections. Produce a findings file — do NOT change the
plan itself; Claude applies fixes after QA.

Scope — read these as the single source of truth:
- components/sections/smileclub/SmileClubOptimization.tsx (the whole plan:
  recommendation, mandate, 30-day delivery plan, digital marketing plan,
  offer & economics, waves + results, corporate playbook, channels,
  measurement).
- .agent-bus/PROJECT-THREAD.md for context and landmines.

What to check, minimum bar:
1. ARITHMETIC: every number that derives from another (budget slices vs
   total, CPL = CPC ÷ CVR ranges, target mixes vs 120, checkpoint sums,
   pipeline coverage ≥72 vs named doors after the Michael Page closure,
   lead-volume math per slice). Flag any pair that cannot both be true.
2. DEFINITIONS: CPL vs CAC vs cost/booking vs cost/meeting — is each used
   consistently everywhere it appears? Is "lead" the same object in the
   mandate spine, the DM plan and the keyword table?
3. CLAIM vs EVIDENCE: every factual claim should be dated and sourced
   (measured / contractual / estimate). Flag any claim that reads as fact
   but is actually assumption, and any estimate not labelled as one.
4. LOGICAL CHAIN: does Diagnosis → Mandate → Funding → Channels → Evidence
   → Controls actually chain? Flag steps that assume what a later step is
   supposed to prove, and orphan sections nothing references.
5. GOVERNANCE HOLES: commitments without owner+date, kill rules without a
   measurement path, targets without a recovery consequence.
6. READER TEST: list the five hardest questions an ex-McKinsey CEO would
   ask after reading, and whether the plan already answers each (cite the
   exhibit) or not (that is a finding).

Deliverable: `.agent-bus/reviews/DN-003-smileclub-rigor.md` on the branch —
findings ranked by severity, each with: exhibit/section reference, the
defect in one sentence, why it fails scrutiny, and a concrete proposed fix
(wording or number). No code changes, no other files.

Definition of done: the review file exists, every finding cites a specific
exhibit/line of content, arithmetic checks show their working, and the
handoff summarizes the top five findings.

Out of scope: editing the plan, code changes, prod anything.
