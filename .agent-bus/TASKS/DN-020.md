## Method (deterministic; record every rule in the handoff)

1. Inventory both files first: list column names and non-empty counts per
   column (column names only, no values) in the handoff.
2. Normalise phones: digits only; drop a leading 00971, 971 or 0; compare
   on the last 9 digits; a UAE mobile is 5 followed by 8 digits. Count
   rows with no usable phone on each side.
3. Normalise names: lowercase, trim, collapse spaces, strip punctuation;
   compare full name and also first + last token.
4. Match tiers, applied in order, each patient matched at most once:
   - T1: exact normalised phone.
   - T2: exact normalised full name AND exact Emirates ID (if both sides
     have EID).
   - T3: exact normalised full name, unique on both sides (if the same
     name appears more than once on either side, count it as ambiguous,
     never pick one).
   Nothing fuzzier than these three tiers. No similarity scores.
5. Classify every post-migration Dr Tosun patient: returning (matched to
   an old-ledger patient) or new (no match). Ambiguous stays its own
   bucket.
6. Write `work/DN-020/out/tosun-id-map.csv` locally (old identifier, new
   identifier, tier). This file stays in work/ and is NOT committed; it is
   the input for a later task that wires the result into the dashboard.
