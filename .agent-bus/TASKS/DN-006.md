# DN-006 — Sheets sync hardening: tests for tab discovery, repeated headers, Excel fallback
Mode: repo
Branch: codex/DN-006
Goal: Claude fixed the Sheets sync on 6 Oct (commit 1591718): the Inhouse Lead
Tracker's tabs were renamed, so every tab failed with "Unable to parse range"
and lane_e.raw_lead_tracker was empty. Lock the fix in with tests and close the
remaining gaps in the adapter, without changing live behaviour.
Context:
- lib/sync/adapters/sheets-adapter.ts: rangeOf() (quoted A1 range), tabTitles(),
  discoverTabs in fetchTabs(), first-non-empty value for repeated headers in
  rowsFromValues(), Excel fallback readExcel() + fetchAny() for "must not be an
  Office file".
- config/sheet-mapping.ts: leadTracker tabs updated to the current names and
  discoverTabs: true. Sources "DN My performance report" and "AMC Checklist"
  are Excel files in Drive; "DN on-site GMB Form" and "Lane Captions" fail with
  "The caller does not have permission" (owner must share them with the
  service account; not a code fix).
- lib/sync/google-auth.ts: getDriveClient() (drive.readonly).
- Follow the existing test setup in the repo (see DN-002's 4 test files for the
  pattern). Mock googleapis; no network, no credentials.
Definition of done:
1. Unit tests: rangeOf quotes titles with spaces, double quotes, apostrophes and
   emoji (e.g. `Lane "E" DR. TOSUN Branch ❤`, `O'Brien`).
2. Unit tests: fetchTabs with discoverTabs reads configured tabs that exist,
   reports missing ones as a warning, and picks up an extra tab only when its
   header row has "Contact Number" + "Inquiry Platform".
3. Unit test: a row with three "Contact Number" columns keeps the first
   non-empty value.
4. Unit test: fetchAny falls back to the Excel path when fetch() throws "This
   operation is not supported for this document. The document must not be an
   Office file." and parses the first sheet (or the configured tab).
5. If readExcel should also handle the Drive file being a Google Sheet shortcut
   or exceed a size limit, add a clear error message (no behaviour change for
   the happy path).
6. `npx tsc --noEmit -p tsconfig.json` and the test command pass; report both
   outputs in the handoff.
Out of scope: changing sheet-mapping ids or tabs, prod DB, deploys, any network
calls, the two permission errors.
