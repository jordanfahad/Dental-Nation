# DN-007 — "Demand to desk": one-page funnel from ad idea to front desk, by treatment theme
Mode: repo
Branch: codex/DN-007
Goal: Mr Akbar asked (6 Oct) whether the demand ideas we run on Meta match real
market demand in Dubai, and where people are lost between the first ad touch and
the front desk. Build a printable one-page view that follows each treatment
theme from market demand → our ad idea → enquiry → front desk → booked →
attended, and flags the biggest leak per theme. Code only: no data in the repo.
Context:
- Themes (classify by regex over names/keywords/text; keep the map in one file,
  e.g. config/demand-themes.ts): Gaps & spacing; Protruding / crooked teeth
  (aligners, braces, ortho); Stains & whitening (coffee, smoking); Bad breath &
  hygiene (cleaning, check-up); Gummy smile; Emergency / pain; Implants &
  missing teeth; Other.
- Stage sources (Supabase schema lane_e, read with the existing server client;
  see lib/growth/channelPerformance.ts and lib/ops/metaLeadsDigest.ts for
  patterns):
  1. Market demand: gmb_search_keywords (month, keyword, impressions) and the
     latest competitor_snapshots row for dentalnation.com (DataForSEO ranked
     keywords with search volume, Dubai). Sum monthly searches per theme.
  2. Our ideation (Meta): meta_ad_insights_raw (campaign_name, ad_name, spend,
     data.actions). Per theme: spend, people who started a chat
     (messaging_conversation_started_7d), net (messaging_user_depth_2_message_send).
     Reuse metaPeople() logic from lib/ops/metaLeadsDigest.ts; never sum events.
  3. Enquiry at the desk: lane_e.leads + raw_lead_tracker (columns
     "Service / Inquiry Type", "Notes / Remarks", "New Update", follow-up
     columns, "Conversion"/"Conversion - Dr Luvi"). Per theme: leads logged,
     reached (a reply or call recorded), no answer, stated barriers (language,
     price, not interested, international number), booked.
  4. Clinic: practo_appointments_raw (complaint, department_name, package_name,
     appointment_status, mr_no) for NEW patient files (mr_no starting "DN") in
     the window: booked, arrived/completed, cancelled/no-show per theme.
- Output: lib/analytics/demandToDesk.ts (pure functions: classify, aggregate,
  leak = largest relative drop between consecutive stages) and a server
  component rendered under the Marketing tab (sub-tab "Demand to desk") with a
  date range (default last full month). One A4-landscape page when printed:
  a theme × stage table with counts and stage-to-stage %, the leak highlighted,
  a "demand vs ideation" column (share of market searches vs share of Meta
  spend per theme), and 3 auto-generated one-line findings.
- Honesty rules (PROJECT-THREAD): label modelled vs measured; counts only;
  never render patient names or phone numbers on this page.
Definition of done:
1. Unit tests for the theme classifier (at least 3 examples per theme, incl.
   Arabic "تقويم", "تبييض") and for the leak calculation.
2. Component renders with empty data without crashing (test or story).
3. `npx tsc --noEmit -p tsconfig.json` and the test command pass; outputs in
   the handoff.
Out of scope: prod DB writes, deploys, new tables/migrations, Meta/Google API
calls, any data committed to the repo.
