## Findings

1. **Blocker: an explicitly stored null rating does not win over fallback or older history.** `lib/performance/reader.ts:69`, with `lib/performance/core.ts:133` and the new null writer at `lib/analytics/benchmark-observations.ts:34`.

   The writer deliberately persists `rating: null` when the review count is zero or the rating is incomplete. `benchmarks()` removes null observations before choosing the latest row, and the reader treats a null value as permission to inject the snapshot. Using the real reader with stored Al Wasl `review_count=0` and `rating=null` for 11 October plus the existing synthetic GBP fixture produced **0 reviews dated 11 October and a 5.0 rating dated 12 October**. With an older competitor rating of 4.8, a newer null rating and zero reviews, the old 4.8 remains visible beside the new zero count. The writer's intended clearing semantics therefore stop at storage.

   Proposed fix: distinguish a missing observation from an observation whose value is null. Select the latest stored observation including nulls, use the snapshot only when that metric has no stored observation, and compute deltas only from two non-null endpoints. Keep an unavailable rating unavailable when the corresponding count is zero. Add reader-level cases for zero count plus stored null plus fallback, and older valid rating followed by null.

   The doctor string is an exact match for an identity in the existing staff mapping, rather than a synthetic test identity. The name is intentionally not reproduced here. This also couples the fixture's branch expectation to the production roster.
