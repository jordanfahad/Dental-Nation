## Storage and calculations

Observations use `lane_e.social_insights`, channel `benchmark`, clinic keys `dr-joy`, `dr-michaels`, and `dental-nation`, metrics `review_count` and `rating`. `day` is the Asia/Dubai date when the weekly fetch completes; `synced_at` records its UTC instant. The exact upsert is `{ onConflict: 'clinic,channel,metric,day' }`. Repeated runs on the same day replace those rows rather than appending duplicates. `integration` identifies the competitor domain or the Al Wasl location path. There is no migration and no 0049 apply step.

Competitor review count sums the existing fetch's matched branch listings. Rating is `round(sum(rating * review_count) / sum(review_count), 1 decimal)`. Empty/failed listing fetches, unknown domains and incomplete review counters write no competitor observation. A zero-review or incomplete-rating observation writes a null rating rather than inventing one; this also clears a previous same-day rating. Missing metadata columns are not guessed: no raw/meta column is defined for this table in the available repository schema or writer types, so optional branch-listing-count metadata is not persisted. Existing Maps matching, depth 20 and 15-listing return cap are unchanged; these remain observed matched listings, not an exhaustive brand census.

Our snapshot reads only the configured Al Wasl `location_path`, with `removed_at IS NULL`, through the existing paginated reader. Other branches and removed reviews cannot contribute. Its rating is the active-review average rounded to one decimal. A failed review read does not manufacture an own zero. One clinic's storage/read failure does not prevent the other clinics' observations; only clinic keys are logged for failures, with no API payloads or credentials. Cache hits perform no observation writes, so an old fetch cannot acquire a new observation date.

The brief shows stored observation dates. A 30-day delta still requires two stored observations exactly 30 days apart on the same profile. A weekly cadence alone does not guarantee those exact endpoints. Instagram remains without a competitor feed or fabricated values. The GBP snapshot fallback applies separately to missing own metrics and has no invented delta.

MTD runs from the current Dubai month's first day through yesterday; the prior period is the whole previous calendar month. On the first day, MTD has no completed days rather than reusing the previous month. GBP values sum available days, count each day once, include recorded zeroes as coverage, and label each incomplete metric `partial month (covered/expected days)`. Missing metrics show Unavailable. All three rows remain visible regardless of the existing branch-log filter.

Tracker demand uses `parseGrossRows`, which already uses DN-018's canonical branch mapper and excludes repeated headers and invalid dates. Repeated legitimate tracker rows remain logged leads; unassigned rows appear only in the footnote. Bookings use the existing strict Growth reader's measured appointment counts, including cancellations and excluding phone-path estimates. Revenue sums the billing feed directly, including unattributed bills and excluding cancelled invoices, with existing `clinicOfCenter` mapping. Al Maher bookings/revenue are Unavailable. Latest bill dates and missing-feed caveats are displayed. Growth calculations themselves are unchanged.
