## Caveats and unattended choices

1. **The existing count grain conflicted with the task.** Growth deduped a phone once within whichever date range was selected. A persistent phone+minute sheet cannot reproduce that count for every range. Website enquiries now use one shared phone+minute selector, so repeat enquiries in different minutes can increase website gross relative to the previous dashboard. Existing source classification and filters remain in Growth; other channels retain their existing count path. This change is also stated in the dashboard enquiry hint. The reconciliation test demonstrates the new common grain, not equality to the former phone-only totals.
2. **Actual source membership is narrower than the task's examples.** The current website count reads untagged `raw_zavis` widget rows and website-classified `leads`. Standalone `ops_form_entries` offer forms and `raw_dn_leads` incomplete bookings do not feed that count, so adding them would expand the requested population. They were not added. If existing website tracker fields identify offer forms or incomplete bookings, H labels them accordingly; otherwise it says booking widget or lead tracker: website.
3. Status and billing use Growth's existing verdicts and file joins, cumulatively since the enquiry date. An event/bill is assigned once to the latest eligible enquiry on its phone; ambiguous file-to-phone joins remain unknown. This prevents repeating the same bill across multiple enquiry rows. Growth's legacy booked population includes cancelled/no-show appointments and its default billing lens includes cancelled bills; those rules are preserved. Billed supersedes attended/booked in the single status column, and summary formulas follow the task's literal status conditions. These are enquiry-cohort outcomes, distinct from the existing appointment-date funnel.
4. The mirror supports ranges from 1 October through the latest sync day. Earlier/all-time dashboard ranges retain their existing numbers and show review unavailable. Review snapshots expire after two hours, and a gross mismatch also withholds feedback. The shared acquisition population still follows Growth's All / Al Wasl scope; the summary's branch split is the requested branch, not a new change to clinic attribution.
5. If a source correction removes/reclassifies an already mirrored enquiry, the sync reports that retained team rows need reconciliation and stops before changing those rows. It never silently deletes team work. Header changes, invalid IDs and duplicate rows similarly stop writes. A concurrent human row sort during the read/write window is not transactional with Sheets; the post-write check detects mismatched machine data where possible.
6. No live Sheets/API/database call, migration execution, email, deployment or push was performed. No credentials were read. The new migration was authored in the repository's numbered-file convention; the Supabase CLI is not installed locally. SQL execution and actual Google formula recalculation were not tested, as this task requires all IO to be mocked. Tests check the formula references and mocked read/write behavior.
7. No existing tracker tab was changed. The unrelated untracked agent-bus files and output/work folders present at task start were left out of the commit.
